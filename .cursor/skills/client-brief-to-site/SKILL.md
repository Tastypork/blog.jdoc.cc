# Client brief to Astro site

1. Read the brief and inspect the repository, package.json, Astro config, routes, components, and existing styling.
2. Summarize the target audience, business offer, primary conversion, supporting conversions, brand tone, required pages, content/assets available, and unknowns.
3. Do not invent business facts. List missing facts as questions or clearly marked placeholders.
4. Propose a sitemap and page section outline before implementation. If the brief is incomplete, make conservative assumptions and label them.
5. Define a compact design direction: visual references described in words, palette, typography, spacing, imagery, component style, and responsive behavior.
6. Build with Astro-first components and the existing styling approach. Keep components reusable where that improves consistency.
7. Include conversion-focused but truthful copy, clear CTAs, and suitable empty/error/success states for interactions.
8. Add page metadata, semantic HTML, accessible labels, and responsive styles.
9. Run available checks and summarize the files changed, decisions made, assumptions, and items requiring client approval.
10. Do not deploy or make paid-service changes unless explicitly requested.
